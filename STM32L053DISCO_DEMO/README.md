# STM32L0538-DISCO E-Paper Showcase

A demonstration application for the **STM32L0538-DISCO** discovery board. A
menu on the board's e-paper display gives access to demos of the display, the
touch sensor, the user button and LEDs, STOP-mode low power, and several
gray-level and fast-refresh rendering techniques.

The project is built with STM32CubeIDE on top of the STM32CubeL0 HAL and
contains a reusable, display-independent e-paper driver for the two display
variants fitted to this board.

## Features

- **E-paper driver** for both display variants of the board, with a common API:
  pixel, line, rectangle and circle drawing, scaled 5x7 text, black/white
  updates and 4-level gray updates
- **Menu UI** operated with the user button and the touch strip
- **Touch sensor** demo: three-zone linear touch sensor read through the TSC
  peripheral, with start-up baseline calibration and debouncing
- **LEDs and button** demo for LD3 (green), LD4 (red) and B1
- **Low-power demo**: the MCU enters STOP mode with the display powered off
  (the image stays on the glass) and wakes on B1
- **Display test** with six examples: basic drawing, 4-level gray, dithered
  16-level gray, dithered gradient, 16 solid gray levels and a smooth gradient
  (the last two use multi-pass refreshes, GDEY0213B74 only)
- **Experimental fast-refresh modes** (GDEY0213B74 only): *Maximum Framerate*,
  *Extreme FPS* and *Extreme Graphics*, which report the achieved frame rate
- **Panel Recovery** routine that runs black/white refresh cycles to reduce
  ghosting
- **Logging** over the ST-LINK virtual COM port

## Hardware

| Item | Details |
|------|---------|
| Board | STM32L0538-DISCO |
| MCU | STM32L053C8T6 (Cortex-M0+, 64 KB flash, 8 KB RAM, LQFP48) |
| Display | E-paper, either **GDE021A1** (172 x 72) or **GDEY0213B74** (250 x 122), depending on board revision |
| Touch | Linear touch sensor (TSC groups G1, G2, G3) |
| Debug / VCP | On-board ST-LINK |

Clocking: HSI16 through the PLL (x4, /2) gives a 32 MHz system clock.

### Pin assignment

| Function | Pin |
|----------|-----|
| E-paper SPI1 SCK / MOSI | PB3 / PB5 |
| E-paper CS / DC / RST | PA15 / PB11 / PB2 |
| E-paper BUSY (high = busy) | PA8 |
| E-paper power switch (low = powered) | PB10 |
| User button B1 (high = pressed) | PA0 |
| LED LD3 (green) / LD4 (red) | PB4 / PA5 |
| USART1 TX / RX (virtual COM port) | PA9 / PA10 |
| Touch G1 (channel / sampling) | PA2 / PA3 |
| Touch G2 (channel / sampling) | PA6 / PA7 |
| Touch G3 (channel / sampling) | PB0 / PB1 |

SPI1 is transmit-only at 2 Mbit/s for normal operation. The fast-refresh modes
temporarily raise the SPI clock (see [Known limitations](#known-limitations)).

## Software requirements

- [STM32CubeIDE](https://www.st.com/en/development-tools/stm32cubeide.html)
  (includes the GNU Arm toolchain, the ST-LINK GDB server and the project
  build system)
- STM32CubeL0 firmware package V1.12.4 (the HAL and CMSIS sources are already
  included under `Drivers/`)
- STM32CubeMX (integrated in STM32CubeIDE) only if you want to modify the
  peripheral configuration in `STM32L053DISCO_DEMO.ioc`
- A serial terminal (115200 baud, 8N1) to read the log output


## Building

1. Open STM32CubeIDE and choose **File > Open Projects from File System...**
   (or *Import > Existing Projects into Workspace*) and select this folder.
2. Build the **Debug** or **Release** configuration with **Project > Build
   Project**.

The Debug configuration can also be built from a shell that has the GNU Arm
toolchain (`arm-none-eabi-gcc`) on its path:

```
make -C Debug all
```

The makefiles in `Debug/` are generated by STM32CubeIDE and are rewritten by it
on every IDE build.

During the build the compiler prints a message naming the selected display
(`E-PAPER BUILD: EPAPER_DISPLAY = ...`). Check that it matches the display on
your board.

## Selecting the display

The two board revisions carry different e-paper panels. Set the display in
`Core/Src/epaper.c`:

```c
/* 0 = GDE021A1 (172 x 72), 1 = GDEY0213B74 (250 x 122) */
#define EPAPER_DISPLAY 1
```

If the wrong panel is selected the display never reports ready; the application
then blinks the red LED and logs an error message on the virtual COM port.

## Flashing and running

1. Connect the board to the PC with the USB cable (ST-LINK).
2. Use **Run > Run** (or **Debug**) in STM32CubeIDE to program and start the
   application.
3. Optionally open the virtual COM port at 115200 baud, 8N1, to see the log.
   The board's solder bridges **SB2** and **SB3** must be closed to connect
   USART1 to the ST-LINK (the default on newer board revisions).

At start-up the display shows a splash screen and the green LED blinks once
after the first successful refresh. Keep your fingers off the touch strip
during start-up, because the untouched baseline is measured then.

## Usage

| Input | Action |
|-------|--------|
| B1 short press | Next menu item / page action |
| B1 long press (about 0.7 s) | Select menu item / go back |
| Touch strip, left | Go back (pages other than the menu) |
| Touch strip, middle / right | Page action or next (depending on the page) |

Menu entries:

| Entry | What it does |
|-------|--------------|
| Touch sensor | Shows the three touch zones and the raw and baseline counts; LD3 lights while the strip is touched |
| LEDs & button | B1 or a touch in the middle cycles LD3 / LD4 through off, green, red, both |
| Low power (STOP) | Powers the display off, enters STOP mode and wakes on B1. The supply current can be measured at jumper JP4 |
| System info | Display variant, system clock, uptime and touch status |
| Display test | Steps through the six rendering examples |
| Maximum Framerate | Fast refresh with a custom waveform; B1 or touch selects the next level, a long press stops |
| Extreme FPS | Same test at a higher SPI clock |
| Extreme Graphics | Animated drawing through the Extreme FPS path |
| Panel Recovery | Runs 8 full black/white refresh cycles; a long press cancels |

A full e-paper refresh blocks for roughly 1-5 seconds depending on the mode.
Input pressed during a refresh is ignored.

## Configuration

| Setting | Location | Purpose |
|---------|----------|---------|
| `EPAPER_DISPLAY` | `Core/Src/epaper.c` | Selects the display variant (see above) |
| `EPAPER_FLIP_X`, `EPAPER_FLIP_Y` | `Core/Src/epaper.c` | Mirror the image if it appears flipped on the glass |
| `EPAPER_BUSY_TIMEOUT_MS` | `Core/Src/epaper.c` | Maximum wait for the display BUSY line |
| `APP_LONG_PRESS_MS` and related timing | `Core/Src/app.c` | Button and touch timing |
| `APP_STOP_DISABLE_DEBUG`, `APP_STOP_ULTRA_LOW_POWER` | `Core/Src/app.c` | Lowest-current STOP configuration |
| `TOUCH_THRESHOLD_COUNTS`, `TOUCH_DEBOUNCE_SCANS` | `Core/Src/touch.c` | Touch detection sensitivity and debouncing |
| Pins and peripherals | `STM32L053DISCO_DEMO.ioc` | Regenerate with STM32CubeMX; user code sections are preserved |

The wake-up interrupt for B1 (`EXTI0_1_IRQHandler`) is implemented in
`board.c`. Do not enable the EXTI0_1 interrupt for PA0 in CubeMX, or the link
fails with a duplicate symbol.

## Known limitations

- The framebuffer is 1 bit per pixel to fit in 8 KB of RAM. Gray images are
  therefore rendered in several passes, and the drawing callback is invoked
  once per pass.
- The 4-level gray waveform of the GDEY0213B74 comes from a driver written
  for a different panel and is not tuned for this one or for temperature;
  gray levels, ghosting and speed can vary.
- Examples 3 and 4 approximate in-between grays by dithering; a single refresh
  cannot produce more than 4 states per pixel.
- Examples 5 and 6 and the fast-refresh modes are available on the GDEY0213B74
  only. On the GDE021A1 the gray examples fall back to the 4 native levels,
  and the fast-refresh entries return to the menu and log "unavailable" on
  the virtual COM port.
- The fast-refresh modes are experimental. They drive every pixel every frame
  with very short waveforms, and *Extreme FPS* / *Extreme Graphics* run the
  SPI at 16 MHz, above the controller's specified write clock of about
  10 MHz. Contrast is deliberately poor at the fast levels, the SPI link is
  not guaranteed to be reliable, and the modes should be run only briefly.
  Use *Panel Recovery* afterwards if ghosting remains.
- The debugger disconnects while the MCU is in STOP mode.

## Third-party components

- **STM32CubeL0 HAL and CMSIS** (`Drivers/`) are provided by
  STMicroelectronics under their own licenses; see the license files in the
  respective directories. They are used unmodified.
- **Font**: `font5x7.h` is derived from the Adafruit GFX "glcdfont" font (BSD
  license).
- **Display sequences**: the GDE021A1 initialization and waveform follow ST's
  `gde021a1.c` from the STM32Cube BSP. The GDEY0213B74 4-gray waveform bytes
  follow the SSD1680 4-gray waveform used by Adafruit's ThinkInk 2.9"
  driver, which in turn follows Good Display's 4-gray demo.
